# 项目上下文

## 项目目标
打造一个高质感、极简风的香薰品牌单页官网，用作客户对外展示与简历投递链接。短期目标是在 2026 年 3 月 15 日（周日）前上线一个稳定、可访问、适配手机与桌面的静态版本；中期目标是在此基础上补充轻量 CMS，让客户能自行替换首页主视觉、产品图和基础文案。

## 技术栈
- Vue 3
- Vite
- Tailwind CSS
- TypeScript
- Vercel（预览与正式部署）
- Sanity（第二阶段内容管理）

## 项目约定

### 代码风格
- 默认使用 TypeScript 与 Vue Composition API。
- 组件保持小而清晰，按页面区块拆分，命名使用 PascalCase。
- 内容结构集中管理并进行类型约束，方便后续从本地静态数据平滑切换到 CMS 数据。
- 布局与样式优先使用 Tailwind 原子类；只有在重复明显时才抽离公共样式。
- 命名优先可读性，不使用过度缩写。

### 架构模式
- 采用单页 Landing Page 架构，核心区块包括：Header、Hero、产品展示、品牌介绍、Footer。
- 第一版以前端纯静态方式交付，内容存放在本地数据文件中，并尽量与未来 Sanity Schema 保持一致。
- 将“内容数据”和“展示组件”分离，后续接 CMS 时只替换数据来源，不重做页面结构。
- 响应式设计遵循 mobile-first，先保证手机端，再优化平板与桌面端。
- 动效以轻量为原则，优先使用 CSS 和浏览器原生能力，避免引入重依赖。

### 测试策略
- 第一版以上线稳定性为优先，重点做人工验收：桌面 Chrome、浏览器移动端模拟、至少一台真机检查。
- 每次部署前必须执行生产构建，确保无构建错误。
- 发布前完成基础冒烟检查：图片是否加载、锚点跳转是否正常、布局是否错位。
- 第一阶段不强制建设完整自动化测试，性能与体验用 Lighthouse 或浏览器工具做收尾检查。

### Git 工作流
- 在初始化 Git 仓库后，优先使用短生命周期分支开发，构建通过后再合并。
- 每次实现尽量对应一个 OpenSpec change，避免多个需求混在同一轮修改中。
- 只有在功能上线并确认交付后，才归档对应的 OpenSpec change。

## 业务背景
- 这是一个偏高端香薰/香氛品牌展示站，视觉层级、留白、字体与图片质量比功能数量更重要。
- 参考风格偏 Jo Malone 一类的极简高级感：克制配色、大面积留白、强视觉产品图。
- 客户当前最需要的是一个“可信、可分享、打开即好看”的线上链接，因此第一阶段以交付确定性优先，而不是后台完整度优先。

## 关键约束
- 第一版必须在 2026 年 3 月 15 日（周日）前交付。
- 第一阶段必须保持静态方案，降低开发与联调风险。
- 域名绑定是加分项，但不能阻塞上线；如 DNS 或实名流程延迟，允许先交付 Vercel 链接。
- 图片必须做压缩与性能优化，避免移动网络下首屏过慢。
- 第二阶段 CMS 必须足够简单，确保非技术客户也能独立完成 Hero 图与产品内容更新。

## 外部依赖
- Vercel：部署、预览链接、HTTPS 证书、可选自定义域名绑定。
- Sanity：后续 CMS、编辑账号、图片资源管理与内容发布。
- 域名注册商 / DNS 服务商：`.com` 域名购买、实名、解析配置。
- 图片压缩工具：TinyPNG、Squoosh 或等效 WebP 转换工具。
