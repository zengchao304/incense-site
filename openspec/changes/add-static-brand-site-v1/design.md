## 背景
当前仓库为空仓库，且第一版存在明确硬截止时间：2026 年 3 月 15 日（周日）前必须上线。客户当前需要的是一个可展示、可分享、视觉质感在线的官网链接，而不是一套完整后台系统。

## 目标 / 非目标
- 目标：
  - 在截止时间前上线一个高质感、双端适配的静态品牌站。
  - 为后续接入 CMS 保留清晰的数据结构与迁移路径。
  - 保证部署简单、修改快速，支持最后阶段替换素材与文案。
- 非目标：
  - 第一版不交付自定义后台或登录系统。
  - 第一版不做电商、下单、支付、会员等复杂功能。
  - 第一版不为炫技而引入复杂动画与状态管理。

## 关键决策
- 决策：第一版采用 Vue 3 + Vite + Tailwind + TypeScript。
  - 原因：搭建快、部署快、对单页展示站足够轻量，适合当前交付节奏。
- 决策：第一版内容全部保存在本地类型化数据文件中。
  - 原因：避免在首版阶段引入 CMS 接入、账号、Schema、联调等风险，同时为后续切换数据源保留接口。
- 决策：先部署到 Vercel，再把自定义域名绑定作为可选增强项。
  - 原因：域名实名、DNS 生效、证书下发都可能影响时效，不能反向阻塞网站上线。
- 决策：动效优先用 CSS 原生过渡和浏览器能力实现。
  - 原因：需要高级感，但更需要稳定、轻量和可控的交付。

## 备选方案对比
- Next.js：如果开发者本身 React 更熟，也可以使用；但对单页静态首版不是必须，额外收益有限。
- WordPress + Elementor：建站快，但更容易出现模板感，且很难稳定做出高质感极简视觉。
- 第一版直接接 Sanity：长期方向正确，但在当前时间窗口内会明显增加建模、接入与验收风险。

## 风险与权衡
- 风险：客户素材和文案到得晚。
  - 应对：先用占位内容搭好完整页面结构，正式素材后置替换。
- 风险：域名购买、实名或 DNS 延迟。
  - 应对：以 Vercel 正式链接作为第一版兜底交付地址。
- 风险：大图导致移动端首屏加载慢。
  - 应对：优先压缩为 WebP，非首屏图片懒加载。

## 迁移计划
1. 第一版使用本地静态数据上线。
2. 将本地数据结构固定为未来 Sanity 内容模型的近似映射。
3. 第二版创建 Sanity Workspace 与内容 Schema。
4. 在不改页面结构的前提下，把本地数据替换为 CMS 数据源。
